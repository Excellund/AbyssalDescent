# Oath/Effigy fixture playback retirement

The final integration snapshot `abyssal-validation-4ff28755b6c048e1a5723f10b043697d` passed all 29 Oath/Effigy assertions, then failed strict shutdown checks with an ObjectDB warning and four retained resources. This is an inherited gameplay fixture; its Oath and Effigy mechanics were not changed for this follow-up.

An independent copy, `abyssal-oath-retirement-660b2a985f9a4d3a81a8bcb8db05f080`, reproduced the same failure immediately with verbose logging. Its six captured post-failure input files were hash-verified before execution. Source comparisons cover all 1,070 frozen inputs; after the correction, only the Oath/Effigy test differs.

The retained resources were the Ogg streams and packet sequences for `impactPunch_medium_002.ogg` and `impactSoft_medium_001.ogg`, held by native `AudioStreamPlaybackOggVorbis` instances. These are reusable impact and swing players. The test's existing tree-exit observer captured only six final playback handles, while its real sound calls created 17. An instrumented failing run reported zero pending exit-observed handles while two earlier weak-observed handles remained alive. Their unsigned IDs, `9223372154748274422` and `9223372155268368408`, exactly match the verbose native leak report.

Godot 4.6.2 keeps a collection of playbacks but exposes only its newest through `get_stream_playback()`. Thus a single exit-time observation does not cover earlier playbacks created by reusing that player. This behavior is visible in the engine's [audio player implementation](https://github.com/godotengine/godot/blob/4.6.2-stable/scene/audio/audio_stream_player_internal.cpp#L303-L310). This diagnosis concerns the fixture's retirement barrier; it does not establish a persistent gameplay leak.

The correction changes only `scripts/tests/test_oath_effigy.gd`. Its existing feedback test double still calls the real sound methods, then weakly observes every returned impact/swing playback through the existing retirement helper. The real world still frees its normal owners; the fixture waits until all observed native handles are gone. No fixed sleep, muted replacement sound, warning suppression, helper rewrite or production audio change is involved.

All 29 prior assertions remain. Three additional checks exercise a reused real swing player, prove both distinct handles are observed before teardown, and verify both retire after owner destruction. Removing just the two new start-observer calls in a disposable counterfactual fails the observation assertion and reproduces the four-resource shutdown failure; the prior 29 assertions still pass.

Final focused verification in `abyssal-validation-e44419cc5471436694f22e9e48de12a7` passes fresh import, 448-script compilation, both guards, Oath/Effigy 32 and shared-attack 38 checks. The corrected verbose replay also passes 32 with clean shutdown. The only ignored native diagnostic is the helper's existing Windows certificate-store message.

Evidence is retained under `.feedback/uncharted-descent-20260912/oath-retirement/`: original full-suite failure, exact-source verbose failure, instrumented and counterfactual sources/logs, corrected logs, focused logs and `receipt.json` with source/log hashes. The trace-only runs include both clean and failing observations; an initial correction attempt's inferred-WeakRef parse error is also retained before its explicit-type fix. These records preserve the investigation rather than replacing earlier failures with later passes. The final full-suite receipt is maintained separately by the workday integration task.
